# Phase 02 — Domain model + first real app checkpoint

This phase replaces the temporary foundation-only experience with the first meaningful BoardOps application slice while establishing the corrected D1 domain model.

Checkpoint scope:
- authoritative D1 domain tables for institution, users, sessions, residents, audit and schema metadata
- seeded local demo data only
- secure-cookie development authentication path
- real application shell with sidebar/header/mobile navigation
- login screen
- dashboard backed by D1 API data
- residents list backed by D1 API data
- responsive glass/motion visual system derived from the audited source DNA
- URL routing, loading states and error states

Financial posting, meals, billing, payments, refunds and reports remain deferred to their dedicated phases. No financial history model may be weakened for UI convenience.
